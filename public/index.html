Technical Task Question: Handling Simultaneous Purchases

Question: "Imagine two users try to buy the last available item at the same time. How would you make sure the stock does not become negative or both orders get confirmed?"

Solution Implemented in this API:

To avoid race conditions, this system does not perform a separate read followed by a write. Instead, it uses:

const product = await Product.findOneAndUpdate( { _id: requestedItem.product, stockQuantity: { $gte: requestedItem.quantity }, // Condition checked atomically }, { $inc: { stockQuantity: -requestedItem.quantity } }, // Decrement applied only if condition met { returnDocument: 'after', session } );
  • Database-Level Atomicity: In MongoDB, document updates are strictly atomic. When two concurrent requests arrive simultaneously, only the first transaction to lock the document succeeds. The second request immediately fails the condition (since stock drops below 1) and returns null.
  • Multi-Document ACID Transactions: The operation runs inside a MongoDB transaction session (session.withTransaction). If any product in an order is insufficient or missing, the entire transaction is rolled back.
  • HTTP 409 Conflict: The winning user receives 201 Created, while the second user receives 409 Conflict: Insufficient stock. Stock never drops below zero.
